# 💡 ایده‌های بات جدید تلگرام — مقایسه و برآورد زحمت

> با محدودیت‌های پلتفرم فعلی ما طراحی شده‌اند:
> **Deployka** (نسخه رایگان، ۱۲۸ مگابایت رم) + **Supabase** (پایگاه‌داده رایگان ~۵۰۰ مگ، اگر ~۷ روز درخواستی نزند پروژه متوقف می‌شود) + مدل‌های OpenAI-compatible ارزان (Dahl / DeepSeek).

---

## ۰) مرزهای سخت پلتفرم — هر ایده باید در این جدول جا شود

| محدودیت | عدد | نتیجه برای طراحی |
|---|---|---|
| رم Deployka | ۱۲۸ مگ | بات متنی + long polling ≈ ۶۰–۱۰۰ مگ ✓ · سِلِنیوم/کروم/پانداس سنگین ✗ |
| حجم Supabase | ~۵۰۰ مگ | رکورد متنی = ۱–۵ کیلوبایت → میلیون‌ها ردیف ✓ · فایل داخل DB ✗ (فقط URL نگه دارید) |
| خواب‌رفتن Supabase | ~۷ روز بدون درخواست | باتِ روزانه خودش پروژه را زنده نگه می‌دارد ✓ |
| Telegram Bot API | آپلود ورودی ≤ ۲۰ مگ · ۳۰ پیام/ثانیه | بات‌های متنی/لینکی آزادند؛ فایل باید کوچک باشد |
| هزینه AI | توکن‌محور | هر پیام = چند صد توکن؛ کوتاه نگه دارید، برای هر کاربر سهمیه (quota) بگذارید |

## ۱) جدول مقایسه کلی

| # | ایده | رم مصرفی | حجم DB | هزینه AI | ایده‌ی اصلی | زحمت ساخت | بازیافت کد بات خبری* | اولویت پیشنهادی |
|---|---|---|---|---|---|---|---|---|
| ۱ | **آموزش انگلیسی روزانه** | ~۶۰ مگ | کم | خیلی کم | لغت + اصطلاح + مثال + آزمون چهارگزینه‌ای در کانال؛ جدول برترین‌ها | ۱–۲ روز | ~۸۰٪ | 🥇 اول |
| ۲ | **قیمت دلار/طلا/کریپتو + تحلیل** | ~۵۰ مگ | خیلی کم | ناچیز | قیمت از API بورس‌های ایرانی (نوبیتکس/والکس) + پست صبحگاهی تحلیلی | ۱–۲ روز | ~۷۰٪ | 🥈 دوم |
| ۳ | **قرآن/حدیث روزانه با توضیح AI** | ~۴۰ مگ | خیلی کم | خیلی کم | متن ثابت روزانه + توضیح کوتاه AI؛ سبک‌ترین ایده | < ۱ روز | ~۸۵٪ | 🥉 سریع |
| ۴ | **خلاصه‌ساز لینک** | ~۸۰ مگ | کم | متوسط | لینک مقاله/یوتیوب → خلاصه فارسی + ۳ نکته کلیدی | ۲–۳ روز | ~۶۰٪ | قوی |
| ۵ | **ثبت هزینه با زبان طبیعی** | ~۵۰ مگ | کم | خیلی کم | «۲۵۰ تومن تاکسی» → پارس AI → گزارش ماهانه + نمودار (quickchart) | ۲ روز | ~۷۰٪ | کاربردی |
| ۶ | **یادآور هوشمند** | ~۴۰ مگ | کم | تقریباً صفر | «هر روز ۸ صبح قرص» — تکرارشونده + پیش‌یادآوری | ۱–۲ روز | ~۷۵٪ | مکمل |

| ۸ | **آرشیو شخصی + جستجوی معنایی** | ~۷۰ مگ | متوسط | کم | ذخیره لینک/نکته + تگ خودکار AI + جستجوی معنایی بعداً | ۲–۳ روز | ~۶۰٪ | هم‌خانواده با ۷ |

\* «بازیافت کد» = درصدی از `main.py` بات خبری (thread زمان‌بند، helper های Supabase، مدیریت کلید AI با fallback، سهمیه کاربر، منوی فارسی) که تقریباً عیناً به بات جدید منتقل می‌شود.

## ۲) جزئیات هر ایده

### ۱) 🥇 آموزش انگلیسی روزانه
- **چرا اول؟** مخاطب ایرانی عظیم، هزینه AI تقریباً صفر (چند صد توکن در روز)، سبک‌تر از بات خبری (فیدپارسر هم نمی‌خواهد).
- **جریان:** thread زمان‌بند هر روز ۸ صبح → لغت + اصطلاح + جمله‌ی مثال AI تولید می‌کند → در کانال + گروه پست می‌شود → آزمون چهارگزینه‌ای inline → امتیاز در Supabase → هر جمعه جدول برترین‌ها.
- **جداول:** `daily_lessons`, `quiz_answers(user_id, lesson_id, correct)`, `scores(user_id, week, points)`.
- **ریسک:** تقریباً هیچ. فقط کیفیت پرامپت.

### ۲) 🥈 قیمت و تحلیل بازار
- **چرا؟** عمومیت بالا؛ بدون RSS، بدون فایل.
- **جریان:** هر ساعت قیمت از API رایگان نوبیتکس/والکس → ذخیره نمونه‌ی ساعتی → ۸ صبح پست تحلیل AI (روند ۲۴ ساعته + هشدار تغییر بزرگ).
- **جداول:** `prices(symbol, ts, price)`, `alerts(user_id, symbol, pct)` — کاربر بتواند هشدار «±۳٪ در روز» بگذارد.
- **ریسک:** محدودیت نرخ API ها؛ با کش ۵ دقیقه‌ای حل می‌شود.

### ۳) 🥉 قرآن/حدیث روزانه
- **چرا؟** سبک‌ترین ایده‌ی ممکن؛ می‌توان در یک روز تحویل داد.
- **جریان:** فایل JSON محلی از آیات/احادیث (از قبل آماده) → هر روز یکی + توضیح کوتاه AI (۲–۳ جمله) → کانال.
- **ریسک:** تقریباً هیچ؛ حتی بدون AI هم کار می‌کند.

### ۴) خلاصه‌ساز لینک
- **چرا؟** اپ‌های مشابه میلیون‌ها کاربر دارند؛ «ابزار روزمره» می‌شود.
- **جریان:** لینک → استخراج متن با `trafilatura` (سبک، ~۱۰ مگ رم؛ آلترناتیو `readability-lxml`) → خلاصه فارسی + ۳ نکته → برگشت. یوتیوب: زیرنویس با درخواست HTTP ساده به `timedtext`.
- **جداول:** `summaries(user_id, url, ts)`, `quota(user_id, day, used)` — مثلاً ۱۰ لینک/روز رایگان.
- **ریسک:** سایت‌های جاوااسکریپت‌سنگین (بدون JS executor نمی‌شود) → پیام واضح «این لینک پشتیبانی نمی‌شود».

### ۵) ثبت هزینه با زبان طبیعی
- **چرا؟** DB-محور خالص؛ AI فقط چند توکن در پیام؛ آمار ماهانه واقعاً به‌درد می‌خورد.
- **جریان:** متن آزاد → AI پارس می‌کند به `{مبلغ، دسته، توضیح}` → ذخیره → `/گزارش ماه` جدول + نمودار quickchart (رایگان، فقط URL عکس).
- **جداول:** `expenses(user_id, amount, category, note, ts)`, `budgets(user_id, category, monthly_limit)` + هشدار عبور از بودجه.

### ۶) یادآور هوشمند
- **چرا؟** CPU تقریباً صفر؛ فقط به thread زمان‌بند موجود نیاز دارد.
- **جریان:** «هر روز ۸ صبح قرص» → AI پارس می‌کند به cron ساده (دقیقه/ساعت/روز) → زمان‌بند هر دقیقه چک می‌کند → پیام + دکمه «انجام دادم / ۱۰ دقیقه بعد یادآوری». پیش‌یادآوری ۱۰ دقیقه قبل.
- **جداول:** `reminders(user_id, text, hour, minute, repeat, last_fired)`.

### ۷) 🏆 «از جزوه‌ات بپرس» — RAG با pgvector
- **چرا متمایز؟** از pgvector رایگان Supabase استفاده می‌کند — ترکیبی که کم‌کسر بلد است؛ نقطه‌ی قوت رزومه‌ای.
- **جریان:** آپلود PDF/TXT (محدود به ۱۵ مگ، فقط کانال خصوصی بات) → استخراج متن با PyMuPDF (سبک) → چانک ۵۰۰ کاراکتری → embedding (سرویس OpenAI-compatible) → جدول `chunks(embedding vector(1536))` → پرسش کاربر → embed همان سوال → RPC `match_documents` → پاسخ AI فقط از چانک‌های مرتبط (هزینه کنترل‌شده).
- **جداول:** `docs(user_id, name, ts)`, `chunks(doc_id, content, embedding vector)`.
- **ریسک‌ها و راه‌حل:**
  - پارس PDF سنگین → سقف صفحه/حجم، پیام واضح.
  - حافظه → کتابخانه‌های پارس lazy-import شوند.
  - هزینه embed → سقف «۱ جزوه در روز برای هر کاربر».
- **نمونه اولیه:** در همین ریپو کنار بات خبری ساخته شد → پوشه‌ی `AskMyPdfBot/` (نمای کلی و ساختار اجرایی).

### ۸) آرشیو شخصی + جستجوی معنایی
- هم‌خانواده‌ی ۷؛ به‌جای PDF، لینک/نکته/نقل‌قول کاربر ذخیره و embed می‌شود.
- بعداً «اون چیزی که درباره‌ی X ذخیره کرده بودم» با جستجوی برداری.
- اگر ۷ را بسازید، این تقریباً رایگان است (همان زیرساخت pgvector).

## ۳) استراتژی پیشنهادی اجرا

1. **شروع:** بات شماره ۱ (انگلیسی روزانه) — سریع‌ترین بازگشت، کم‌ریسک‌ترین، و همان را می‌توان عمومی کرد.
2. **موازی:** pgvector را در همین پروژه یاد بگیرید (بات ۷) — مسیر ایده‌های ۷ و ۸ باز می‌شود و تمایز فنی واقعی است.
3. **پایداری:** برای هر بات جدید:
   - جدول `usage_quota` برای کنترل هزینه AI (سهمیه روزانه per-user).
   - یک ردیف heartbeat روزانه بنویسید تا Supabase پروژه را متوقف نکند.
   - سقف سخت برای اندازه فایل ورودی و طول پاسخ AI.
4. **زمان‌بندی Deployka:** هر بات یک سرویس جدا (بهترین راه مدیریت رم)؛ اگر دو بات سبک دارید می‌توانید موقتاً در یک پروژه ادغام کنید و بعداً جدا کنید.

## ۴) جمع‌بندی یک‌خطی

> از سبک به سنگین: **قرآن/حدیث (نیم‌روز) → انگلیسی روزانه (۱–۲ روز) → قیمت/تحلیل (۱–۲ روز) → هزینه/یادآور (۲ روز) → خلاصه‌ساز (۲–۳ روز) → آرشیو معنایی (۲–۳ روز) → RAG جزوه (۳–۵ روز)**.
> با هر کدام که شروع کردید، دو چیز را از روز اول رعایت کنید: **سهمیه AI** و **heartbeat دیتابیس**.
